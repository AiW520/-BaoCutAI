# 从长视频里切短视频

> 用户有一个长视频（访谈、讲座、直播回放、口播），想从中挑出几段能单独发布的短视频时用：读转写挑出各自成立、开头有钩子的片段，把每段创建成可编辑的子视频，用户在编辑器里接着调。需要视频的转写。不用于按主题从零做一个新的短视频，也不用于把整段口播剪干净（用剪口播）。

刷到这条短视频的人没看过长视频，也不知道前面讲了什么。头三秒没抓住他，他就划走了；中间出现「刚才说的那个」，他就不知道在说什么。所以一段短视频要自己站得住：开头就是钩子，只讲一件事，停在结论上。

最容易挑坏的样子：按长视频的章节切。一章十分钟，开头铺垫三句才说到点子上，结尾停在「接下来我们看」，里面还夹着两个亮点。那是长视频的一段，不是一条短视频。

交付的是**可编辑的子视频**，不是 mp4：每一段用 `baocut videos derive` 建成父视频旁边的一个独立视频，用户在编辑器里继续调入出点、画面和字幕，要文件时再导出。

## 1. 先有转写

没有转写（kind 为 speech 的文档）时先转写，告诉用户转写在进行。挑片段只需要原文的词时间；润色和翻译只在用户要时才做。视频已经有章节时，章节有助于定位话题，但章节的边界不是短视频的边界。

## 2. 读文稿，挑片段

读带时间的文稿：`baocut export` 导出字幕（kind `subtitles`、format `srt`）或带时间码的文稿（kind `transcript`、format `md`、timestamps `true`），`baocut jobs inspect` 等到 completed，读 outputs 里的文件。这些时间是剪辑后时间线上的时间，和 `baocut videos derive` 的 start、end、取帧用的是同一个时钟。

**句界怎么取**：找句子的起止不用 dump 整份 speech 文档。`baocut documents read` 读转写时，返回的 translationBasis.sentences 每一句带 start、end（秒），但那是**素材时钟**；`baocut videos derive` 的 start、end 是**时间线时钟**。父视频从 0 秒开始、原速、没有剪口地播放这条素材时，两者相同，可以直接用句子的 start、end 定区间。先确认这一点：用 `baocut videos inspect`（或 facts）看视频项的 sourceIn 是否为 0、速度是否为 1、有没有剪口。任一条不满足，就用上面导出的 SRT 或文稿里的时间线时间，或者把素材时间换算成时间线时间再传，不要把素材时间直接当时间线时间用。

挑几段（用户说了个数就照它，没说 3–5 段），每段单独看得懂。时长按用户给的范围（可能是 15–30、30–60、60–90 秒，1–3 分钟或自定义）；没给时每段 30–60 秒。**不设平台上限**：超过 3 分钟只提一句，YouTube 不按 Shorts 收，其余照做。

- **在文稿里找这四种**：反常识的说法、情绪的高点、密集的干货、带转折的小故事。文稿只是线索：找到之后，用 `baocut videos frames` 在那几秒取几帧看画面（有没有可看的、说话人在不在画面里），再结合上下文判断是认真说的还是玩笑，然后列为候选。帧是素材画面，不含字幕与叠加的元素。
- **一个短视频只讲一件事**：一段里有两个亮点时，拆成两个短视频，或只留一个。
- **开头那句就是钩子**：一个反直觉的结论、一个具体的数字、一个问题。一段要铺垫三句才说到点子上，就把起点往后挪，或者不要这一段。
- **结尾自成一体**：停在结论或包袱上，不停在「接下来我们看……」这种半句话上；结尾是「关注、订阅」一类的话时，把终点提前到上一句。
- **不依赖上下文**：没有「刚才说的那个」「第二点」这类要看前面才懂的指代。
- **开头 3 秒要有人说话**：没有时把起点挪到第一句话；不在前面加标题卡。
- **入点与出点落在句子边界**：入点取开头那句第一个词与它前一个词之间停顿的中点；出点取最后一个词与下一个词之间停顿的中点。不切进词里。边界拿不准时，略放宽一点：用户在编辑器里收比补回来容易。
- **停顿短于一帧（约 40 毫秒）时，「取停顿中点」不成立**：中点落不到一个整帧上，取整会吃进下一个词或吞掉上一个词。运行时现在会把边界收进停顿里（终点不吃下一个词的起点，起点不吞上一个词的结尾），返回的 range 是实际采用的值，可能和你传的差几帧。创建后核对返回的 range 与你要的差值：差得多、或开头结尾的词因此被截，就换一个边界重新创建，不要放着不管。
- **访谈：优先一个人不被打断的整段**。允许从回答的第一句完整句开始。开头依赖上文的句子（「另一种说法是」「这就像刚才说的」）不要当开头，往后挪到能自己成立的那一句。采访者夹一两句短插话可以接受，但要在理由里写明在哪几秒、说了什么。
- **台标、边框、水印是 go/no-go 检查**：取了帧之后看角落与边缘有没有台标、赞助条、烧进去的字幕、边框。要用的裁框会把它们切掉一半或留下半个字时，换裁框或换片段，并告诉用户做了什么选择；不要留着半个台标交付。
- **已经切过的不再找**：用户提到（预填的话里有「已经切过的不再找」）或你怀疑切过时，`baocut space list`（videoId 填父视频）看已派生的子视频（origin.source 为 `derived`）和它们的区间，新的候选避开这些区间。
- 视频剪辑过时，文稿里的时间已经是剪辑后的；用户想按剪辑前的原素材切时，先和用户确认用哪个版本。

对比一下（只是示意）：

不好：`12:00–14:30`，从「好，那我们接下来聊聊成本这块」开始，到「这个我们待会儿再展开」结束。

好：`12:41–13:22`，从「我们算过，一条视频的成本其实只有三块钱」开始，到「所以贵的从来不是生成，是返工」结束。

后一段头一句就是数字，停在结论上，中间没有指代前文的话。

## 3. 先创建还是先给用户看

- 用户的话里有「找好就直接创建成视频，不用先问我」这类意思（参数页预填的话默认带这一句）：找好直接进第 4 步，不在会话里一段段确认。
- 没有这句，或用户说「先给我看」：先列候选等用户挑。每段写入点与出点、开头那句原话、亮点（一句话）、为什么能单独成立、发现的问题（例如画面上有烧进去的字幕、分屏或并排的双机位、角落的台标或赞助条，竖屏裁切时会被切掉一半；访谈里另一人说话时画面里没有说话人）。取了帧的说看了哪几处；没看过画面的就说没看过。按把握从大到小排，用户挑定后再创建；用户说「你定」时自己定，并说明理由。

不需要在会话里反复问边界：子视频保留着整份时间线与文稿，用户在编辑器里点划掉的句子就能把它放回来。标题和理由用用户说话的语言写。

## 4. 创建子视频

对每一段调用 `baocut videos derive`：

- `video` 是父视频，`start`、`end` 是剪辑后时间线上的秒，`name` 用片段标题。
- **画幅**：用户要 9:16 时 `width` 1080、`height` 1920；1:1 时 1080×1080；保留原画幅（或没提）时不传 width、height 和 fit。不要为了「高清」把小尺寸放大。
- **取景**：传了画幅就给 `fit: "cover"`（铺满、裁掉多余）。用户说「居中」和「我自己定」都先居中建好；后者告诉用户可以在画布上拖动画面调取景。这里没有跟随人物或发言人的自动取景，只有居中和一个静态裁框（`crop`）：用户要「跟着说话的人」时如实说做不到，先放到主讲人身上建好，请用户在编辑器里自己调；不要承诺会随人移动。
- **取景「自动」怎么做**（提示词写的是：在片段里均匀抽几帧，看说话的人在画面哪一侧，把裁框放到他身上；找不到人就居中）：按人脸检测的结果定裁框，不靠看图估位置。
  1. 用 `baocut videos frames` 在这一段内**均匀抽 8–12 帧**（`range` 给这一段、`count` 10），不是 2 帧。每帧的 `faces` 是检测到的人脸框，`x`、`y`、`w`、`h` 按帧的宽高归一化到 0–1，对应素材画面，正好是 `crop` 的坐标。
  2. **认出主讲人**：把各帧的脸按中心横坐标（`x + w/2`）归成人，相差不到 0.1 的算同一个人；面积（`w × h`）很小的脸（背景里的观众、屏幕里的小画面，比如不到 0.003）不算。出现的帧数最多的是主讲人；帧数相近时取平均面积大的那个。
  3. **按脸中心定裁框**：取主讲人在这些帧里脸中心横坐标的中位数 `cx`。保留整个高度时，裁出的宽度比例 `cw = (画布宽 ÷ 画布高) × (原画高 ÷ 原画宽)`；`left = cx − cw/2`，限制在 0 到 `1 − cw` 之间，`right = 1 − cw − left`，`top`、`bottom` 给 0。实例：16:9 的原画出 9:16，`cw` = 0.316；脸中心在 0.30 时 `crop` 给 left 0.142、right 0.542。
  4. **多机位**：看主讲人不在的那几帧（切到另一个人或全景）。优先选**不切机位**的整段；切了就把裁框放在主讲人身上，并在回复里告诉用户哪几秒的画面是别人。片段**不要以对方的反应镜头开头**。
  5. **没有脸**：所有帧的 `faces` 都是空的，居中（不传 `crop`），并如实说没找到人脸。结果的 `detector` 为 null 时是检测器不可用，不是没人：这时退回看帧图片，估主讲人在画面哪一侧，照第 3 步的算法给 `crop`，并说明这次是看图估的。
- `chapters: false`：30 秒的子视频不该带着父视频的整份章节。
- `captions` 按用户的字幕要求：要字幕给 `true`（默认），不要给 `false`。用户只要原文或只要译文时，字幕层的选择按他的话，做不到的（例如没有译文）如实说。
- **译文**：`baocut videos derive` 默认把父视频的译文与译文字幕层一并带到子视频；旧格式的译文会自动升级后再带。返回里出现 `translations-skipped` 警告时，告诉用户哪种语言没带上。
- **核对返回值**：`range` 是实际采用的边界，对一下和你要的差多少（见上面的短停顿）；`captions[].cueCount` 只数落在区间内的 cue，不是整份字幕的条数，用它判断字幕有没有建出来、数量是否合理。
- 每一支创建后，会话里会自动出一张视频卡，不需要再贴路径。同一区间与设置重复调用会认回已有的子视频（`reused` 为 true），不会多建。

子视频是什么：整份复制父视频的时间线与文稿，区间之外的部分被剪掉，用户在编辑器里点划掉的句子就能把它放回来；原视频不动。所以不要把哪一支移入回收站，也不要为了「改边界」重建一支，让用户在编辑器里拖。

去口癖、收紧停顿会改动整个视频，不在这里做；用户要时先说明影响，按剪口播的做法在子视频上处理。

### 要如实转述的 warnings

创建结果里的 warnings 逐条告诉用户，用大白话：

- `multiple-assets`：父视频不止一份主素材，这一版只按主素材剪，别的素材跟着移动，请用户在编辑器里检查。
- `items-not-restorable`：整段落在剪掉区域里的其他轨片段不会随「恢复」回来。
- `range-not-exact`：区间之外有一部分没能剪掉（主素材盖不到），入出点会比要求的略宽。
- `captions-skipped`：字幕层没建成，说明原因，告诉用户可以在字幕面板里再建。
- `translations-skipped`：父视频的这份译文没能带进子视频（旧格式换不过来），子视频里没有这门语言；告诉用户是哪种语言，可以在子视频上重新翻译。

拒绝的错误（父视频有代码画面、区间为空等）如实说，不绕开。

## 5. 成片文件

默认交付是子视频，不是 mp4。用户明确要文件时，再对子视频调用 `baocut export`：kind `video`、format `mp4`，`baocut jobs inspect` 等到 completed，把 outputs 里的 path 告诉用户。时间线上的字幕默认烧进成片（burnCaptions），不要字幕时给 `false`。用户想直接导出、不建子视频时，也可以沿用在父视频上按 ranges 导出的老办法，每段一个 `{start, end}`。

## 6. 要避免的

- 不要按章节切，不要让一段里有两个亮点。
- 不要从铺垫开始，不要停在半句话或「关注订阅」上。
- 不要留着「刚才说的」「第二点」这类指代。
- 不要切进词里；不要在前面加标题卡。
- 没说「先给我看」的，不要一段段停下来问边界；说了的，不要替用户定，除非他说「你定」。
- 不要把没看过的画面说成没问题；不要吞掉 warnings。
- 不要承诺跟随说话人的取景；不要只抽两帧就定裁框。
- 不要把素材时钟的句子时间当时间线时间直接传；不要放着返回的 range 与要的差很多而不核对。
- 不要让片段以对方的反应镜头或依赖上文的句子开头；不要交付被切了半个台标的裁框。
- 不要导出了 mp4 却说成交付，除非用户要的就是文件；不要把子视频移入回收站。

## 7. 交付

收尾时逐支列出，写给用户看：

- 标题、在父视频里的入点与出点、时长、画幅与分辨率。
- 开头那句原话，一句话说为什么挑它。
- 做了什么、没做什么：画幅与取景（原画幅 / 居中，可以在画布上拖）、字幕（有 / 没建）各一句。
- 创建时的 warnings，没有就写没有。
- 发现的画面问题（烧进去的字幕、台标或赞助条、分屏或相邻画面、插话时说话人不在画面里）：有就写；看过而没有写「没看到」；没看画面就写没看。
- 最后一句：子视频在编辑器里可以继续调，想把划掉的话放回来点那句就行；要 mp4 再说。
